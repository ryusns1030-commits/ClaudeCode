# Claude Codeで高品質なアニメーションリールを作るための制作プレイブック

このファイルは、Claude Codeが制作したInstagramリール（Co.Co.Motivate／note記事原作、54.7秒）のノウハウをまとめたものです。ChatGPTなど別のAIに渡し、次回の依頼文（プロンプト）作りや方針検討に使うことを想定しています。

---

## 1. 結論：品質を決めた5つの要素

1. **音声を先に作り、映像はその実測値に合わせる（音声ファースト）**
   ナレーションを1行ずつ合成し、WAVの実際の長さから字幕・シーン・演出のタイミングをすべて自動計算した。映像の時間を先に決めて音声を後から合わせる方式はとらない。
2. **「発話の瞬間」と「演出」を同期する**
   音声合成エンジン（VOICEVOX）が返すモーラ（音の単位）ごとのタイミングを使った。「にじゅうだい」と言った瞬間に「20台」が表示されるように、キーワード単位で演出キューを自動生成した。口パクも母音（あいうえお）単位で同期した。
3. **すべての動きをフレーム番号で決める（決定論的に作る）**
   Remotionの `useCurrentFrame` ／ `interpolate` ／ `spring` ／ `Sequence` だけで動かした。CSSアニメーション、`Math.random()`、時刻に依存する処理は使っていない。乱数は「フレーム番号から計算するハッシュ関数」で代用した。そのため何度レンダリングしても同じ結果になる。
4. **完成したMP4そのものを検査し、直して再レンダリングする**
   コードを見て完成とはしなかった。MP4からフレーム画像を抜き出して目視し、ffmpegで黒画面・映像の停止・無音・音量・音割れ・音ズレを数値で検査した。見つかった問題7件を修正し、再レンダリングした。
5. **事実を守るための仕組みを最初から入れる**
   台本と原作の事実を1行ずつ対応させた表を作った。イメージ図には画面上に「※イメージです」と表示し、「効果が出た」とは言わない構成にした。

## 2. 制作パイプライン（実際に動いた構成）

```
台本データ(script.json)
  → 音声合成(VOICEVOX, 1行ずつ) → 各行WAV + モーラ単位のタイミング
  → タイムライン生成(Python) → timeline.json（シーン範囲・字幕・演出キュー・口パク、すべてフレーム単位）
  → BGM/効果音の合成とミックス(Python+numpy) → master.wav
  → 映像(Remotion/React/TypeScript)がtimeline.jsonを読んで描画
  → MP4レンダリング → ffmpegで検査 → 静止フレームを目視 → 修正 → 再レンダリング
```

| 工程 | 使用技術 | 要点 |
|---|---|---|
| 動画 | Remotion 4.0.x, React 19, TypeScript | 1080×1920, 30fps, H.264(yuv420p, BT.709)+AAC |
| 音声合成 | VOICEVOX Engine（Docker, ローカル, 無料） | Docker Hubが制限された場合は `mirror.gcr.io/voicevox/voicevox_engine:cpu-latest` から取得 |
| 字幕の改行 | BudouX + CSS `text-wrap: balance` | 日本語を文節単位で改行し、2行のバランスを揃える |
| フォント | Noto Sans JP, M PLUS Rounded 1c（OFL） | ファイルをローカルに同梱し、`@remotion/fonts` で読み込む |
| BGM・効果音 | Python + numpy で手続き的に合成 | 外部素材を使わないので権利問題がない |
| 検査 | ffprobe / ffmpeg / Playwright | 下記のチェックリストを参照 |

## 3. 各工程の具体的なノウハウ

### 3-1. 台本
- **字幕用テキストと読み上げ用テキストを分けて持つ。**
  - 例：字幕「20台」→ 読み「にじゅうだい」
  - 例：字幕「2択」→ 読み「にたく」
  - 例：字幕「ChatGPT」→ 読み「チャットジーピーティー」
  - 例：字幕「1〜5枚」→ 読み「1枚から5枚」
- 数字の読みは、エンジンが返す読みデータ（kana）で確認する（例：3433 → サンゼンヨンヒャクサンジュウサン）。
- 初稿は58秒あった。話速1.25倍と表現の圧縮で発話を約45秒にした。尺を決める主な要素は「話速・行間の間・見せ場の余韻」の3つ。
- 見せ場（「20台」「未確認」など）の後には、シーンごとに1秒前後の余韻（hold）を設定した。

### 3-2. 音声（VOICEVOX）
- 使った設定：話者 春日部つむぎ（ノーマル）、speedScale 1.25、intonationScale 1.15、48kHz。
- **規約の確認方法**：エンジンAPIの `/speaker_info`（話者ごとの規約）と `/engine_manifest`（エンジンの規約）で取得できる。
  - 春日部つむぎ：「VOICEVOX:春日部つむぎ」と表記すれば商用利用可。
  - No.7など、商用利用に事前確認が必要な話者は避けた。
- 動画の最後と台本にクレジットを表記した。

### 3-3. 同期の仕組み（最重要）
- 行の間に0.16秒、シーンの間に0.38秒の間を入れ、各行の開始時刻を決めた。
- **口パク**：`audio_query` の子音長・母音長からフレームごとの母音を求め、`"aaii--uuoon..."` のような1本の文字列にした。キャラクターはフレーム番号でこの文字列を参照し、口の形を切り替える。
  - 子音部分の短い隙間で口が閉じ切ると、口元がちらついて見える。そこは「小さく閉じた口」を保つと自然になる。
- **演出キュー**：「行番号＋読みのキーワード」を指定すると、そのモーラの開始フレームを自動で求める。例：`("viewsReveal", 2, "ニジュウダイ")`。
- 効果音も同じキューのフレームに配置したので、映像・音声・効果音がずれない。

### 3-4. キャラクター
- SVGをReactコンポーネント化した。描画関数はフレームに依存しない純粋関数にし、動きは外側のラッパーで与える。この分け方で、静止SVG素材の書き出しにも同じコードを使い回せる。
- **デザインの要点**：
  - 白いスクワークル型の頭、ネイビーのバイザー画面、発光する目と口
  - 浮遊する手（胴体とつながっていないので、ポーズを自由に付けられる）
  - アンテナ、胸の上向きグラフのエンブレム
- **キャラクターは全編を通して1つのレイヤーに置いた。** キーフレーム（位置・大きさ・表情・ポーズ）で画面上を移動させ、シーンが変わっても同じ個体が動き続けるように見せた。
- **動き**：
  - まばたき：ハッシュで2.6〜4秒間隔、6フレームかける
  - 体の浮遊と影の伸縮
  - 表情切り替え時の軽い伸び縮み（スクワッシュ）
  - 手振り、指差し、考える、バンザイ、驚き
  - 退場と再登場
- 表情は5種類：通常、驚き、考える、笑顔、真剣。

### 3-5. 画面設計
- **セーフエリア**（InstagramのUIに隠れない範囲）：
  - 上部約200pxと下部約330pxには重要な情報を置かない。
  - 字幕帯は y=1340〜1590、文字は54px Black。
- **配色**：ネイビー、ブルー、ホワイトが基本。強調色は珊瑚色（悪い数字や「未確認」）だけに絞った。
- **見出し**：上部にストーリーズ風の進行バーとシーン番号のチップを置き、今どこを見ているかがわかるようにした。
- **数字・固有名詞**：字幕内でシアン色にハイライトした。
- **実在サービスのUIやロゴは模倣しない。** オリジナルの「〜風」イメージ図にして、画面上に注記を入れた。
- **シーン切り替え**：8フレーム重ねてクロスフェードし、少し上下に動かしてぼかした。

### 3-6. BGM・効果音
- BGM：104BPMのローファイ調（エレピ風コード、ベース、アルペジオ、ドラム）。
- **ナレーション中はBGMを自動で約−7dB下げた**（サイドチェーン・ダッキング）。
- 結論シーンではドラムを抜き、空気を締めた。
- 効果音：ウーッシュ（場面転換）、ポップ（要素の出現）、ティック（カウントアップ）、ドスン（悪い数字）、スタンプ、タイピング、チャイム。
- **最終の音量**：True Peak −1.8 dBFS、約 −17.7 LUFS。初回は +0.3 dBFS で音割れの恐れがあったため、ピークを −2 dBFS に揃えて解決した。

## 4. 品質検査チェックリスト（毎回実施する）

**数値で検査するもの（ffprobe / ffmpeg）**
- [ ] 解像度 1080×1920、30fps、想定フレーム数
- [ ] H.264 / yuv420p / TVレンジ / BT.709（フルレンジの yuvj420p になっていないか）
- [ ] AAC 48kHz ステレオ、映像と音声の尺が一致している
- [ ] 黒画面：`blackdetect`
- [ ] 映像の停止：`freezedetect`
- [ ] 無音：`silencedetect`
- [ ] 音量と音割れ：`ebur128=peak=true`（True Peak は −1 dBFS 以下）
- [ ] デコードエラー：`ffmpeg -v error -f null`
- [ ] 音ズレ：MP4の音声とミックス元WAVの相互相関で0msか

**目視で検査するもの**
- [ ] 完成MP4から10〜25時点のフレームを抜き出し、横に並べたシートで目視する（文字切れ、はみ出し、重なり、キャラクターが文字を隠していないか）
- [ ] 発話中の顔を数フレームおきに並べ、口の形が変わっているか確認する
- [ ] 字幕どうしが重なっていないか（タイムラインで機械的に判定）

**正直に報告すること**
- [ ] 人の耳での試聴など、AIが確認できない項目は「未検証」と明記する

### 実際に見つかった問題（次回は最初から防ぐ）
1. キャラクターがカードや注記の上に重なった → キャラクターの配置用の領域をあらかじめ確保する。
2. チャットUIで、後から出る要素が既存の要素に重なった → 最終状態の大きさで枠を設計する。
3. 吹き出しが中身の出現前から空のまま大きかった → 中身の出現に合わせて伸ばす。
4. 字幕が文節の途中で改行された → BudouX と `text-wrap: balance` を使う。
5. 口元がちらついた → 発話中の短い隙間は小さく閉じた口にする。
6. 前のカードの消え残りが決め台詞に重なった → 消えるタイミングを次の字幕の開始に合わせる。
7. 音割れの恐れ、フルレンジ色空間 → ピークを正規化し、`setColorSpace("bt709")` を指定する。

## 5. 事実とライセンスの守り方

- 台本の各表現と原作の事実を、1対1で対応させた表を作る（`script.md` にある）。
- **禁止表現をあらかじめ決めておく。** 今回は「増えた」「成功した」「改善した」と言い切る表現。
- 図解用のサンプル値（曜日の色、投稿の有無、アンケートのバー）は事実ではないので、画面上に「※イメージです」と表示する。
- 顧客名、アカウントID、個人情報は出さない。
- **Remotionのライセンス**：無料で使えるのは個人と従業員3名以下の企業まで。それを超える企業が商用で使う場合は Company License が必要。
- 音声のクレジットは「VOICEVOX:話者名」。フォントはOFLのものを同梱する。

## 6. 次回Claude Codeに依頼するときのプロンプトの型

```
あなたは映像ディレクター兼Remotionエンジニアです。
原作：<URL または事実の箇条書き>
事実の制約：<変えてはいけない数字・日付>／禁止表現：<例：「成功した」>／出してはいけない情報：<顧客名など>
仕様：1080×1920, 30fps, 目安<尺>秒, MP4(H.264 yuv420p BT.709 + AAC), 日本語ナレーション＋同期字幕
キャラクター：<方向性・配色>（オリジナル、既存キャラの模倣禁止）

進め方（必ず守る）：
1. 音声ファースト：VOICEVOX(ローカル)で1行ずつ合成し、実測の長さから字幕・シーン・演出のタイミングを自動計算
2. モーラ単位の同期：キーワードを発話した瞬間に演出を入れ、口パクは母音単位
3. フレーム基準：useCurrentFrame/interpolate/spring/Sequenceのみ。CSSアニメーションとMath.randomは禁止
4. 字幕用テキストと読み上げ用テキストを分け、数字の読みは返ってきたkanaで確認
5. BGM・効果音は権利がクリーンなもの（自前合成可）。ナレーション中はダッキング、True Peak −1 dBFS以下
6. セーフエリア：上部200px・下部330pxに重要情報を置かない。字幕は54px前後、BudouXで改行
7. 完成MP4から静止フレームを抜き出して目視し、ffmpegで黒画面・停止・無音・音量・音ズレを検査。問題があれば修正して再レンダリング
8. 未検証の項目は未検証と報告する
成果物：reel.mp4, thumbnail.png, script.md, storyboard.md, character.svg, report.md
```

### さらに品質を上げるために、人が補うとよいこと
- **原作記事に直接アクセスできる環境を用意する。** 今回は note.com がネットワーク許可外で、本文を読めなかった。
- **完成後に人が試聴し、気になる箇所を伝える。** AIは音を聴けないため、アクセントやBGMの聴感は人の確認が必要。
- 尺の優先度（「45秒厳守」か「事実優先」か）を最初に指定する。
- 既存の再利用資産として `cocomotivate-reel-test/` を指定すると、`scripts/script.json` の差し替えだけで別の記事の動画を作れる。
